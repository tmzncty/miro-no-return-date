# 网络交换与长距传输

这条故事弧把第45—53章以来分散出现的室环、远驿、门房、区域节点、货运网络和远距通信重新收束，并在第236—237章推进到“局部交换设备普通化 + 陆地长距再生干线区域试用”。

## 早期基础

- 第45—50章逐步形成室环、远驿、门房、多媒质节点和区域调度思路。早期节点依赖第四号通用转报计算器，能够处理地址、巨帧、路由、拥塞与媒质转换，但成本和复杂度决定它不适合永远放在每一个普通路口。
- 第50—53章开始把信息先于货物和车辆流动写入现实物流；铁路沿线远驿节点逐渐增加，但地方媒质、供能、维护和线路条件仍高度不一致。
- 第93章远驿第二版引入会话租期、退出确认和静窗；第六型关系演算机把局部异步握手、条件时和关系生命周期推进到更成熟阶段。
- 第105章明确提出“灰岭以外，机器还没有学会彼此说话”：问题不是外地没有先进机器，而是不同年代、机构和厂商系统彼此隔离，跨系统需要人工转抄和专用转换。
- 后续王都、维尔兰和镜潮湾经验进一步证明：互联不是统一消灭差异，而是让不同系统在明确边界下交换状态和内容。

## 第236章：交换设备普通化

第一型公共交换柜完成约八个月多场景试用后正式量产放行，意味着局部网络不再需要在每个学校、市场、诊所或工坊部署一台通用转报计算器。

关键变化：
- 八口、十六口、三十二口规格进入普通部署；
- 可更换媒质片适配不同地方线路；
- 独立端口缓存和局部异步交换，让慢设备不拖住整个网络；
- 席位—端口关系具有租期，支持设备迁移与旧口静窗；
- 冗余连线出现环回时能够限制未知泛送，保留已知点对点通信并等待人工处理；
- 交换柜只负责交换，不获得应用权限，也不取代门房和区域远驿路由节点；
- 地方维修者可以更换常用模块，不必等待灰岭工程师。

南市集普通摊位“价格牌为什么慢”的场景成为成熟性的真正标志：网络设备开始像水管和配电柜一样进入日常，不再要求每次使用都被当成技术事件。

## 第237章：再生中继长距干线

局部交换成熟后，故事重新追问王国尺度的远距离传输。早期多媒质远驿能够送短文本，但在数百至上千公里距离上，模拟波形展宽、噪声、相位误差与逐段补偿会累积。

陆地联合试验采用**再生中继**：每段只负责可靠抵达下一维护站；中继站完成接收、判决、校验并重新生成干净信号，而非把上一段的波形和噪声一起放大。

第一阶段利用既有铁路通信廊道完成一千一百多公里级全长业务测试，采用不同媒质混合，但统一再生行为。

网络进一步引入：
- 分段确认、端到端完整校验；
- 受控在途窗，提高长往返距离下的吞吐；
- 主干中断时转入低容量备路，优先维持安全/文字小报片并暂停大块传输；
- 恢复后先进入观察而非立即宣称正常；
- 完整链路由终端、本地交换、门房、区域路由、长距干线多层职责组成。

白榆旧书铺作为普通远端用户参与验证，把第105章父母家小显文端的钩子重新接回：真正成熟的长距网络允许“一只花盆开了三朵”“一本旧书找到了”“好”这样的轻消息单独跨越一千多公里。

## 第259章：计划休眠进入长期支持层

鸦石谷北坡低功率短报点的巡检附片暴露出一个成熟技术的新失配：节点和网络协议本来已经理解静窗 / 计划休眠，但区域长期支持平台为了方便连续远端监测，仍按默认频率反复询问设备，打断休眠并在连续低风日真实消耗蓄能余量。

地方人员自行完成拆除—复装复现，确认问题在远端巡检 / 服务层而非风轮、蓄能或短报点本体。灰岭没有发明新的低功率协议，只把既有语义延伸到长期支持合同。

第一版只形成窄范围“计划窗口可观察”服务档：
- 地方责任方声明正常交换窗口，窗口外不等同故障；
- 服务面板显示下一预计观察时间，不以持续沉默自动生成工单；
- 应有窗口缺失、连续失败或真实维护指标越界才进入异常；
- 窗口变更保留来源与生效时间；
- 不能为了满足监测频率单独唤醒已进入约定休眠的站点；
- 是否可采用该档取决于真实公共后果与备用路径，高连续性医疗 / 消防 / 道路等不能自动沿用。

这条线把“断联后怎样运行”从设备 / 协议继续推进到服务、维护和合同：成熟互联不仅要让机器表达差异，也要让组织层愿意保留这些差异。

## 第288章：线路没有故障，普通消息却开始等得太久

- 白榆旧书铺一条关于车站北门修雨棚、弥宁返程入口和家中第一场霜的普通文字消息，用十七小时九分才抵达灰岭。端到端校验正确、没有中继掉线、没有切入应急备路，因此“线路可用 / 未记录端到端故障”在设备层仍为真，却已经不足以描述普通用户实际经历。
- 区域周报确认这不是单条偶发：随着学校、档案、商行、铁路和区域维护等真实业务增长，多数普通短文本仍在正常范围内完成，但最慢的一小部分开始在多个区域交界累计等待十小时以上，最长超过一天。问题从“能不能可靠送到”推进到“谁可以一直晚到”。
- 当前后台大块本来只使用剩余容量，并没有名义上高于普通文字；但一批数据一旦进入受控在途窗，就不能被每个后来出现的小报片随时打断。不同区域各自一次“再等一点”会在长距路径上累积，形成高尾部等待。该现象来自真实利用率增长与局部准入行为，不等同于设备故障或有人恶意降级私人通信。
- 联合试用没有把所有普通消息升级成紧急业务，也没有让运营系统读取正文判断“值不值得快”。固定永久预留普通容量和允许大块随时抢占式中断都存在明显容量、校验与运营成本，因此暂不写成标准答案。
- 灰岭—南线两个区域交界先启动四周受限的**后台准入分段让行**试验：在大块之间提供可预期让行点，并让已经等待明显变长的普通队列在下一让行点获得更高出队机会；它仍不能越过安全、气象和明确时限业务，也不保证所有普通文字低延迟。试验只观察队列年龄、块大小、在途窗、容量、后台完成时间、重复校验量与运营工时，不读取正文。
- 公众状态在已有明显积压时，先窄范围增加“普通文字当前可能隔夜”提示。该提示只描述当前路径实际队列，不把隔夜等同故障，也没有发布全国统一新状态词。
- 第288章继续维持成熟技术的证据边界：第一晚受限试验只能确认没有立刻把线路弄坏；父亲下一条消息两小时多抵达也不能证明新规则已经成功。后续应等四周数据或其他区域实践再判断是否扩大。

## 当前边界

- 第一型公共交换柜已经是普通产品，不再是实验概念。
- 再生中继长距干线进入区域试用，但全国高容量骨干尚未完成。
- 海底主动中继仍是研究问题；不能因为陆地路线成立就直接照搬到镜潮湾—岚汀海缆。
- 网络互联不会直接获得对物理执行设备的控制权，门房、安全联锁和本地责任继续保留。
- 远端“可观察”不等于“必须持续在线”；计划静窗是可声明的正常状态，但必须与真实失联、漏窗和高连续性业务分开。
- 长距业务现在进一步暴露“可用不等于等待可接受”的运营问题；普通业务不应因“不紧急”而被默认可以无限次顺延，但当前仅有灰岭—南线四周受限试验，尚无全国统一公平调度规则或固定延迟承诺。
- 后续可继续推进容量、长距多路复用、跨国互联、资费、隐私、维修劳动、网络故障与“谁有权决定路由 / 优先级”等问题。
